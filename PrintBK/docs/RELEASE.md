> **Release Engineering Manual for Windows Counter Application**  
> Covers version bumping, packaging standalone NSIS installer, code signing hooks, and update feed distribution.

## 2. What the Installer Packages

`PrintBK-Counter-Setup-<version>.exe` is a single, self-contained Windows executable installer created via **electron-builder** and **NSIS**.

Inside the single `.exe`:
1. **Embedded Node.js Runtime & Chromium** (via Electron v33+). The client PC requires **no** Node.js, pnpm, or Git.
2. **Supervised Print Agent Subprocess**: Watchdog supervisor with auto-restart on crash and rotating logs in `%APPDATA%\PrintBK\logs\agent.log`.
3. **Staff Counter Window**: Embedded browser window loading the live staff web application (`/staff/`) so staff UI improvements deploy instantly over the air with zero installer downloads.
4. **Bundled Silent Print Engine**: Pinned SumatraPDF 64-bit portable executable (`bin/SumatraPDF.exe`), verified by SHA-256 checksum at build time.
5. **Document Conversion Engine**: Checks for existing Microsoft Office (via COM automation) or LibreOffice.
6. **Windows Auto-Start**: Registers the application to start automatically on Windows user login.

## 3. Step-by-Step Release Workflow

### Step 3.1: Bump Version Number
Update the version string in `counter-app/package.json`:
```json
{
  "name": "printbk-counter",
  "version": "1.1.0"
}
```

### Step 3.2: Compile & Build Installer
Run the production build:
```bash
pnpm build:installer:prod
```
The installer will be generated at:
`counter-app/dist/installer/PrintBK-Counter-Setup-1.1.0.exe`

### Step 3.3: Publish to Update Feed
1. Tag the release in Git:
   ```bash
   git tag v1.1.0
   git push origin v1.1.0
   ```
2. Create a GitHub Release (or upload to your static release bucket):
   - Upload `PrintBK-Counter-Setup-1.1.0.exe`
   - Upload `latest.yml` (generated by electron-builder containing SHA-512 hashes)
3. Existing installed workstations will detect the update via `GET /server/api/counter/version`, download it in the background when not printing, and apply it seamlessly on next restart.

## 4. Code Signing & Windows SmartScreen

### 4.1 Unsigned Installer Behavior (Default)
When distributed without an EV (Extended Validation) code-signing certificate, Windows SmartScreen will display:
> *"Windows protected your PC — Microsoft Defender SmartScreen prevented an unrecognized app from starting."*

**Exact clicks for the shopkeeper:**
1. Click **More info** (under the warning banner).
2. Click **Run anyway** (at the bottom right).
3. The setup window opens immediately.

### 4.2 Adding a Code-Signing Certificate (Future)
When you acquire an EV or standard code-signing certificate (`.pfx` file):
1. Set the following environment variables prior to running the build:
   ```bash
   $env:CSC_LINK = "C:\path\to\certificate.pfx"
   $env:CSC_KEY_PASSWORD = "YourCertificatePassword"
   ```
2. Re-run `pnpm build:installer:prod`.
3. `electron-builder` will automatically detect `CSC_LINK` and sign both the internal binaries and the outer setup `.exe` using Microsoft `signtool.exe`. No code changes are required.

## 5. Security & Zero Secret Guarantee
- The installer executable contains **ZERO** pre-baked secrets, API tokens, or shop passwords.
- Workstation credentials are established dynamically on first launch when the shopkeeper enters the `COUNTER_SETUP_CODE`.
- Tokens are encrypted at rest on the client PC using Windows DPAPI (`CryptProtectData` via Electron `safeStorage`).
